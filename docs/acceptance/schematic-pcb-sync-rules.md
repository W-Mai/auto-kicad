# Synchronization with custom-rule files

Every synchronization profile rejects actual PCB or project mutations when a custom-rule file is present, including an empty file. Source references, values, paths and net names can participate in arbitrary rule conditions. Effective netclass records and unchanged DRC counts do not independently establish complete custom-rule behavior. Observation and verified byte-identical no-op plans remain available; no-op plans grant no mutation approval and create no execution record.

Actual KiCad 10.0.7 production MCP qualification covers 15 profiles: the preceding runtime exposes a metadata mutation preview on a conditional-rule board; corrected ordinary and region paths reject metadata/net changes, empty/conditional files and project changes while preserving all inputs. Exact board/project no-ops remain available. Two custom-rule-free positive controls actually publish metadata through approval, commit and native readback. All owned native handles exit and private snapshots are released. Complete records, runtime identity and quality evidence are in [the machine-readable record](schematic-pcb-sync-rules.json).

The ordinary positive control accepts the original owned baseline. The region positive control uses a separately native-saved owned baseline with explicit default text thickness. The original region input correctly rejects when native refill adds that unselected field; its failed attempt and exact native difference remain retained. This does not qualify arbitrary native serialization changes or complete custom-rule evaluation. Existing scale, publication and recovery contracts remain applicable.
