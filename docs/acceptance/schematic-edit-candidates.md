# Typed schematic edit candidates

`compile_edits` produces immutable candidate files from an observed project, its native component identities, exact source bytes and typed operations. It changes existing-symbol values and custom properties, DNP/BOM/board flags, symbol position/quarter-turn/mirror transform, and explicit symbol deletion. Wire segments, junctions, no-connect markers and local/global/hierarchical labels support creation, mutation and deletion. Electrical label shapes are typed; local labels cannot carry one. Reference annotation and footprint assignment are reserved for their separate operations.

Each target uses a physical file, object kind and UUID. Existing UUID uniqueness is checked per physical file; new UUIDs are allocated once against the union of existing identities. An explicit `FileAllInstances` scope is required for reused files, and candidate changes list every affected instance path. Isolated physical edits to a reused file reject. Requests contain 1–128 operations affecting at most 32 files; source and candidate files retain the 32 MiB per-file and 128 MiB total bounds.

The compiler resolves operations against immutable before bytes, rejects overlapping or repeated writes, and retains exact before/after spans. Every untouched interval remains byte-identical. Existing property formatting and unknown retained child data remain unchanged. Symbol transforms map attached property positions through the relative orthogonal transform and keep field text upright; wires are not dragged implicitly. Creation keys and generated UUIDs remain in the candidate changes. Editor locks, source drift, unsupported versions, invalid identities, ambiguous fields and zero-length wires reject before publication. No filesystem publication is performed by this API.

Quoted source atoms use KiCad string decoding for escaped Unicode bytes, quotes, backslashes, newline/tab and hexadecimal/octal escapes without changing source spans. Raw multiline quoted tokens and invalid decoded UTF-8 reject. The rules are defined by [KiCad 10.0.7 DSNLEXER](https://gitlab.com/kicad/code/kicad/-/raw/10.0.7/common/dsnlexer.cpp). Native component source UUID lists are canonicalized as unordered identities while preserving duplicates for validation; native unit slots keep their original order.

## Native acceptance

Actual KiCad 10.0.7 passed 4 profiles based on two installed examples: ECC83 in formats 20250114 and 20260306, the multichannel main sheet, and a reused multichannel child sheet. Each profile executes six candidate cases: property/flag changes, a moved/rotated/reflected resistor, wire/marker/label creation, their mutation, their deletion, and symbol deletion. The shared child case changes all 4 instances and rejects an isolated-instance request.

Property changes retain full source-pin connectivity and native values preserve Chinese text, quotes, backslashes, newline and tab. Moving the resistor disconnects exactly its affected pins while preserving unrelated groups. Wire creation merges the expected resistor-pin groups per instance; changing its endpoint restores the baseline partition. Independent local/global/hierarchical label objects exercise text, position, orientation and electrical-shape editing. Deleting added objects restores both complete pin connectivity and exact baseline ERC. Symbol deletion removes only the expected source-pin identities. These electrical test candidates intentionally exercise changed/error states and are not approved production schematics.

All original examples, retained baselines and owned input/configuration copies remained unchanged. Private audit directories were removed, and no editor was launched. Full quality passed formatting, capability matrix, warning-denied all-target Clippy and 522 tests with zero failures and 15 environment-dependent tests ignored. Existing actual fixed-circuit CLI/MCP regression passed separately in 4.60 seconds.

Failed attempts remain available. Multi-unit source UUID export order and native string escapes required shared parser corrections. A conflicting-label candidate produced different `multiple_net_names` diagnostic identities across actual repeated ERC runs; the audit rejected it. 4 raw reports retain that evidence. Diagnostic identities are not discarded to make conflicting candidates pass.

## Reproduction and scope

Run `check-schematic-edits OWNED_SCHEMATIC OWNED_CONFIG NEW_OUTPUT [REFERENCE]`, where the default reference is R1. Both input roots require `.auto-kicad-audit-owned` containing `schematic-audit-acceptance` followed by a newline. The example retains each native candidate, source replacements, complete ERC, connectivity and context evidence, and checks source/configuration preservation and private-directory cleanup. The retained `accept-schematic-edits.py` runs the 4 profiles; [schematic-edit-candidates.json](schematic-edit-candidates.json) records results and source/evidence hashes.

This is a candidate compiler with native-copy acceptance. Symbol creation from approved catalogs, annotation, footprint assignment, sheet/hierarchical-pin editing and new child files remain unimplemented. Public general-edit requests, reviewed native connectivity/ERC deltas, multi-file publication/recovery and schematic-to-PCB synchronization also remain required. Native CLI evidence does not establish GUI save compatibility or a complete Codex editing lifecycle. The existing fixed-circuit MCP request is unchanged.
