# Closed synchronization with authored and generated regions

`kicad_inspect_project.schematic_pcb_sync` accepts `regions: true` with `kind: "observe"`. This opt-in profile returns complete authored `zones` and native `region_ownership`. Omitted or false `regions` retains the existing observation, intent and journal encodings. Saved PCB and schematic documents must be closed.

`intent.zone_nets` selects complete authored regions by observed `{uuid, net}`. Source pad, copper and zone selections must agree at every original physical contact. A whole-zone terminal union constrains ownership; it never merges disconnected islands into a graph edge. Locked, rule-area, foreign, duplicate, redundant and conflicting selections reject. Removal cannot drop a contacted terminal. Replacement retains exact connected physical contacts and complete pad correspondence.

Candidates use two independent native refill executions under the final selected project settings, frozen resources and copied configuration. Complete authored definitions, filled copper and generated copper/mask records must agree. Composition changes only approved net/metadata/template spans and matched fill/generated spans. Unchanged fill remains byte-identical. Known native ordering of direct footprints, named properties and electrical metadata is a comparison grammar; complete values, identities, unknown fields and ordered physical geometry remain checked. The exact private project-root property is separately bound and restored to its original source form.

Region plans contain a complete `regions` expectation: authored fill changes and generated before/after inventories. Pass it unchanged alongside `differences`, complete `drc` expectations and any project/class expectations to `kicad_preview_change`. Missing or altered region expectations reject. Generated private DRC identities are stable, collision-checked and bijective; full authored/generated content remains protected. Raw native outputs retain their own hashes even when native generated serialization order varies.

`remove_manual` requires an explicit observed board-only footprint UUID. Ordinary `remove` retains its existing policy. Both reject eligible source ownership, locks, external references and retained physical/zone contacts.

Publication retains execution4/5 and recovery5/6. Explicit region baselines add a versioned ownership profile and complete generated signature where needed. Three exact native input/output artifacts are fsynced and hash-bound beside each preview. Recovery validates the archive, current policy, exact publication prefix and immutable dependencies before restoring; fresh actual source/native/connectivity/class/DRC proofs precede clearing pending state. Later user bytes remain untouched. Project-changing fills publish project settings before PCB bytes; an unchanged PCB is omitted.

The profile is qualified on macOS arm64 and KiCad10.0.7 with32MiB PCB inputs,4096 physical endpoints,256 total authored/generated regions and4MiB public messages. These are refusal bounds, not a qualification of every maximum-size combination. Custom-rule region changes and generated/custom-rule observations reject. Source/template families outside their existing qualified contracts remain unsupported. This is a saved-document workflow; it grants no interactive rerouting, GUI editing or manufacturing-readiness claim.

Actual acceptance covers a two-island plane, conflicting desired nets, metadata publication, class-driven filled-copper changes with ordered two-file publication, generated copper/mask content, explicit manual removal, source-bound template addition/replacement/removal, connected same-contact replacement and displaced-contact refusal. Actual Codex calls rename source pads, tracks and a zone together. Ordinary and generated actual writer SIGKILL controls require fresh approvals, retain later user bytes, restore complete native baselines and permit a subsequent commit. A complete NFC copy retains166 original copper objects; its seeded /ANT region is an acceptance fixture, not an antenna design recommendation or a final three-project product gate.

[Machine-readable evidence](schematic-pcb-sync-regions.json) records runtime hashes, initial refusal receipts and resumed postconditions. Existing [synchronization](schematic-pcb-sync.md), [connected replacement](schematic-connected-replacement.md) and [pinless lifecycle](schematic-empty-components.md) contracts remain applicable.

Malformed released-owner metadata in a source-lifecycle harness requires separate cleanup qualification. Ten identity-bound trees were archived and manually cleaned after acquiring their native OFD leases; that failed harness does not establish automatic cleanup. The archive retains the original malformed bytes for diagnosis. Successful resumed publication/recovery checks remain separate from this cleanup qualification.
